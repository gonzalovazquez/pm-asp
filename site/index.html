Agentic Skills Platform · Proof of Concept

Turn a chat message into a real product document.

PM ASP is an AI-native platform for enterprise product & engineering work. A conversational interface, backed by a catalog of reusable skills, routes each request with an LLM, runs an orchestrated workflow with human approval where needed, grounds it in enterprise knowledge (Jira, Confluence, GitHub), and produces a real, versioned artifact.

Why it matters

The work PMs repeat, done as reusable skills

Writing a PRD, summarizing requirements, identifying risks — the same shape of task, over and over, each needing the same context gathering and write-up. PM ASP makes each one a first-class, governed, reusable capability instead of a one-off prompt.

🧩

Reusable skills

Every capability is a versioned skill with its own knowledge, required context, and workflow — curated by a TPM, not hard-coded.

🧠

LLM intent routing

An LLM reads the message and the skill catalog and picks the right skill, returning a stable execution plan. A keyword router is the offline fallback.

🔌

Grounded in your systems

Context comes from Jira, Confluence and GitHub through a governed MCP layer — one server per credential boundary, keys never held by the app.

✅

Human-in-the-loop

Skills can require approval before an artifact is finalized. Approval state is owned by the workflow engine, kept separate from conversation memory.

📄

Real, versioned artifacts

Outputs are stored as markdown artifacts — never overwritten. A new run is a new version; retrieval always reads the latest.

🔁

Provider-agnostic

Every LLM call flows through one gateway. Swap Anthropic for a local Ollama model with a config change and zero application code — ideal for air-gapped, regulated environments.

Layered, modular, single seam per concern

Trust boundaries

Browser↔API is CORS-scoped; internal services trust the Compose network; each MCP credential (Atlassian, GitHub PAT) lives with its server, never in the app.

Stable contract

The router always returns {skill, context_sources, requires_approval, status, candidates} — the schema and workflows depend on that shape staying fixed.

Deliberate omissions

No executions table (n8n owns approvals) and no tenant_id yet (multi-tenancy is an M9 concern) — decisions, not gaps.

Built on

An open-source stack

Decided for modularity and Docker/Kubernetes parity.
